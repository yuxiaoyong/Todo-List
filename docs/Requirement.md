# 产品需求说明

> 最后更新：2026-06-05

---

## 1. 产品定位

**Todo List** 是一款面向**个人用户**的**本地桌面**待办管理工具。

| 维度 | 要求 |
|------|------|
| 用户规模 | 单人使用，无账号体系 |
| 部署形态 | 桌面应用（Windows 优先），离线可用 |
| 数据归属 | 数据完全存储在用户本机 |
| 产品风格 | 轻量、响应快、与系统桌面集成深 |
| 非目标 | 不做云同步、团队协作、复杂项目管理 |

---

## 2. 目标用户与场景

### 目标用户

- 需要在电脑上快速记录与跟进日常任务的个人用户
- 重视隐私与数据可控，不希望依赖在线服务
- 希望用快捷键、托盘、窄条窗口等桌面能力提升效率

### 典型场景

1. **随时记下一件事**：全局快捷键打开快速捕获，输入后回到当前工作
2. **按项目 / 标签整理**：用分类和标签筛选，列表或看板查看进度
3. **写清任务细节**：详情里用富文本和附件补充说明
4. **不忘截止日期**：系统通知或邮件在到期前 / 到期时提醒
5. **极简常驻**：边缘吸附窄条列表，不占任务栏，扫一眼待办
6. **数据可迁移**：换机或重装时通过 Zip / JSON 备份恢复

## 3. 功能需求

### 3.1 任务（Must）

| ID | 需求 | 验收标准 |
|----|------|----------|
| T-01 | 创建、编辑、删除任务 | 支持标题、正文、优先级、截止日 |
| T-02 | 标记完成 / 未完成 | 列表、看板、极简均可切换 |
| T-03 | 软删除与回收站 | 误删可恢复；支持永久删除 |
| T-04 | 任务排序 | 列表与极简支持拖拽排序；置顶任务单独分区 |
| T-05 | 自动保存 | 详情编辑无需手动点保存 |

### 3.2 组织（Must）

| ID | 需求 | 验收标准 |
|----|------|----------|
| O-01 | 分类管理 | 可创建、删除、按分类筛选 |
| O-02 | 标签管理 | 多标签、OR 筛选 |
| O-03 | 看板视图 | 自定义列、拖拽任务 между列 |
| O-04 | 搜索 | 中文关键词全文检索 |

### 3.3 表达（Should）

| ID | 需求 | 验收标准 |
|----|------|----------|
| E-01 | 富文本正文 | 基础格式与图片 |
| E-02 | 附件 | 上传、预览、打开、删除 |
| E-03 | 负责人字段 | 详情可填写（无协作逻辑） |

### 3.4 桌面集成（Must）

| ID | 需求 | 验收标准 |
|----|------|----------|
| D-01 | 系统托盘 | 关闭窗口不退出；托盘可唤起主界面 |
| D-02 | 单实例 | 重复启动不打开多份进程 |
| D-03 | 全局快捷键 | 快速捕获、主 / 极简切换可配置 |
| D-04 | 极简模式 | 窄条列表、边缘吸附、失焦缩边 |
| D-05 | 多窗口 | 主界面、极简、快速捕获、独立详情 |
| D-06 | 极简不占任务栏 | 极简模式下任务栏无应用图标 |

### 3.5 提醒（Should）

| ID | 需求 | 验收标准 |
|----|------|----------|
| N-01 | 到期提醒 | 有截止日的未完成任务可触发提醒 |
| N-02 | 提醒通道 | 系统通知；可选邮件 |
| N-03 | 提醒策略 | 可配置提前小时数、重复间隔、总开关 |
| N-04 | 通知可点击 | 系统通知点击可打开对应任务 |

### 3.6 数据（Must）

| ID | 需求 | 验收标准 |
|----|------|----------|
| S-01 | 本地持久化 | SQLite + 附件目录 |
| S-02 | Zip 备份 / 恢复 | 用户可手动备份与还原 |
| S-03 | JSON 导出 / 导入 | 支持迁移与合并导入 |
| S-04 | 数据目录可访问 | 设置中可打开本机数据路径 |

### 3.7 个性化（Should）

| ID | 需求 | 验收标准 |
|----|------|----------|
| P-01 | 主题 | 浅色、深色、跟随系统 |
| P-02 | 语言 | 简体中文、English |
| P-03 | 窗口透明度 | 全局可调 |
| P-04 | 快捷键自定义 | 全局快捷键可改键 |

## 4. 非功能需求

### 4.1 性能

| ID | 需求 |
|----|------|
| NF-01 | 常规任务量（数百条）下列表与搜索响应流畅 |
| NF-02 | 自动保存不阻塞编辑体验 |
| NF-03 | 冷启动后可进入主界面并完成基本操作 |

> 大规模（上千条）场景下的虚拟滚动与 SQL 侧筛选为后续优化项（见 Plan.md）。

### 4.2 可靠性

| ID | 需求 |
|----|------|
| NF-04 | 数据库操作失败有明确错误信息 |
| NF-05 | 备份 / 恢复 / 导入前有确认，失败有提示 |
| NF-06 | 附件与任务删除时清理孤立文件 |

### 4.3 安全与隐私

| ID | 需求 |
|----|------|
| NF-07 | 数据默认仅存储本机，不上传云端 |
| NF-08 | 富文本展示前 HTML 消毒 |
| NF-09 | 邮件密码等敏感配置存本地 settings，不明文展示 |

### 4.4 可维护性

| ID | 需求 |
|----|------|
| NF-10 | 数据库结构变更通过版本化迁移 |
| NF-11 | 前后端职责分离：UI → Store → Command → Repository |
| NF-12 | 用户可见文案支持 i18n 扩展 |

### 4.5 兼容性

| ID | 需求 |
|----|------|
| NF-13 | 主要目标平台：Windows 10/11 |
| NF-14 | 使用 Tauri 2 官方插件能力（通知、快捷键、窗口状态等） |

## 5. 约束与原则

### 5.1 刻意不做

以下能力**不在**当前产品范围内，避免范围膨胀：

- 用户账号、登录、云同步
- 多人协作、评论、指派工作流
- 甘特图、依赖关系、工时统计
- 插件 / 脚本扩展市场
- 移动端 App

### 5.2 设计原则

1. **本地优先**：所有核心功能离线可用
2. **桌面原生感**：托盘、快捷键、多窗口、边缘吸附优先于 Web 范式
3. **渐进增强**：先打通单人日常闭环，再叠加日历、重复等进阶能力
4. **数据可带走**：备份 / 导出格式稳定、可读
5. **少即是多**：不为少数场景引入过重配置

## 6. 需求与实现对照

| 类别 | 状态 |
|------|------|
| Must 需求 | 已基本满足（见 [Feature.md](./Feature.md)） |
| Should 需求 | 大部分已满足；通知 i18n、分类编辑 UI 等待完善 |
| 进阶需求 | 未开始（见 [Plan.md](./Plan.md)） |

### 已知差距（相对本文 Should / 体验预期）

1. 无「今日 / 已过期」专用入口
2. 搜索无关键词高亮
3. 分类 / 标签缺少完整管理 UI
4. Rust 层系统文案未完全国际化
5. 无自动备份与 DB 损坏恢复引导
6. 大数据量下客户端时间筛选可能成为瓶颈

## 7. 术语表

| 术语 | 含义 |
|------|------|
| 主窗口 | 三栏完整界面（`main`） |
| 极简模式 | 窄条任务列表窗口（`minimal-todo`） |
| 快速捕获 | 全局快捷键唤起的置顶输入窗 |
| 软删除 | `deleted_at` 标记，任务进入回收站 |
| 合并导入 | JSON 导入时与现有数据合并，非覆盖 |
